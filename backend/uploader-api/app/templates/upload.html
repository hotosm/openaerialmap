Where is the imagery?

Any host works if the link is reachable over public HTTPS and returns the .tif itself. Preview pages, folders and unrelated archives are refused; the ODM archive case is handled below.

NodeODM

https://your-node/task/<task-uuid>/download/all.zip, plus ?token=<token> if the node was started with one. The node has to be reachable from the internet. We extract only odm_orthophoto/odm_orthophoto.tif from the archive. An old orthophoto.tif NodeODM link is upgraded automatically.

WebODM

Make the task public, then paste its orthophoto.tif or all.zip download URL. Private API links still need a login token that OpenAerialMap does not collect.

ScaleODM, S3 and other object storage

Paste the presigned or public URL as it is. S3, Google Cloud Storage, Azure Blob, R2, B2 and MinIO all serve the file directly, so we change nothing. Start the import while the signature is still valid.

OneDrive and SharePoint

Share the file itself, not its folder, and copy the link. Paste it as it came: we switch it to a direct download.

Dropbox

Same again - share the file, copy the link, paste it as it came.

Google Drive

Set access to Anyone with the link, copy it, and paste it as it came. Drive is the least reliable of these: it sometimes shows a "can't scan this file" page for a large file, which we cannot click through. If the import fails, download the file and upload it instead.

What will not work

Private WebODM downloads, MEGA, WeTransfer and iCloud Drive need a login, a POST, or in-browser decryption before any bytes appear. Download the orthophoto and upload it as a file instead.
